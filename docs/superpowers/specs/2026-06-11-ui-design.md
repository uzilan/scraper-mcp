# Scraper MCP UI Design

## Overview

React + Vite + Tailwind frontend for the scraper-mcp REST API. Served by FastAPI as static files at `/ui`. Runs in the same process as the existing MCP + REST server.

## Layout

Full-viewport, no page scroll. Two columns: fixed left sidebar + flex-fill main area.

### Left Sidebar (240px)

**Namespace panel (top):**
- Shows active namespace name, highlighted with blue border
- Lists other available namespaces; clicking one switches to it (`POST /namespaces/{name}/use`)
- Delete button on each namespace (`DELETE /namespaces/{name}`)
- Text input + Add button to create a new namespace (`POST /namespaces`); creating auto-activates it

**Indexed pages list (bottom, scrollable):**
- Fetched via `GET /index/pages` for the active namespace
- Each entry is a link that opens in a new tab
- Refreshed when the active namespace changes or after any index operation completes

### Main Area

**Tool bar (top strip):**
Four radio buttons: `Search` (default), `Index Page`, `Index Tree`, `Discover Links`.
Switching tools only changes the input area — history is unaffected.

**Input area (below tool bar):**
- **Search:** free-text query input, Search button
- **Index Page:** URL input, Index button
- **Index Tree:** URL input + Depth number input (default 2), Index button
- **Discover Links:** URL input + Depth number input (default 2), Discover button

**Unified history panel (scrollable, fills remaining height):**
Single chronological list of all tool results — Search, Index Page, Index Tree, Discover Links — regardless of which tool is currently selected. Newest entry at top; older entries rendered at reduced opacity. Each entry shows:
- Color-coded tool badge (Search = indigo, Index Page = green, Index Tree = orange, Discover Links = pink)
- Query or URL used, plus depth if applicable
- Summary count (results, pages indexed, links found)
- Result body appropriate to the tool:
  - Search: list of text chunks, each with source URL link
  - Index Page / Index Tree: plain confirmation message
  - Discover Links: list of discovered URL links

## Tech Stack

- **React 18** with functional components and hooks
- **Vite** for build tooling
- **Tailwind CSS** for styling (dark theme, `#0f172a` base)
- **httpx / fetch** for REST calls to the FastAPI backend
- FastAPI `StaticFiles` mount at `/ui` serving the Vite build output (`dist/`)

## Data Flow

1. On mount: `GET /namespaces`, `GET /namespaces/current` → populate sidebar
2. On namespace change: `GET /index/pages` → refresh pages list
3. On tool submit: call appropriate REST endpoint → prepend new entry to history state
4. History state is in-memory (React state); cleared on page refresh

## API Endpoints Used

| Action | Endpoint |
|---|---|
| List namespaces | `GET /namespaces` |
| Current namespace | `GET /namespaces/current` |
| Create namespace | `POST /namespaces` |
| Switch namespace | `POST /namespaces/{name}/use` |
| Delete namespace | `DELETE /namespaces/{name}` |
| List indexed pages | `GET /index/pages` |
| Index page | `POST /index/page` |
| Index tree | `POST /index/tree` |
| Search | `GET /search?q=...` |
| Discover links | `GET /links?url=...&depth=...` |

## FastAPI Integration

`router.py` gains a `StaticFiles` mount:

```python
from fastapi.staticfiles import StaticFiles
app.mount("/ui", StaticFiles(directory="ui/dist", html=True), name="ui")
```

The Vite build step runs as part of deployment / development setup. During development, Vite dev server proxies API calls to `localhost:8000`.

## File Structure

```
ui/
  index.html
  package.json          # react, vite, tailwindcss, @vitejs/plugin-react
  vite.config.js        # proxy /namespaces, /index, /search, /links → localhost:8000
  tailwind.config.js
  src/
    main.jsx
    App.jsx             # root layout (sidebar + main)
    components/
      NamespacePanel.jsx
      PagesList.jsx
      ToolBar.jsx
      InputArea.jsx
      History.jsx
      HistoryEntry.jsx
    hooks/
      useNamespaces.js  # fetch + mutation helpers for namespace API
      usePages.js       # fetch indexed pages
    api.js              # thin fetch wrappers for all endpoints
```

## Error Handling

API errors shown inline as a red error entry in the history panel (same card structure, red badge). No modal dialogs.

## Testing

- Unit tests for `api.js` fetch wrappers (mock fetch)
- Component tests with React Testing Library for NamespacePanel, InputArea, HistoryEntry
- Integration test: mount App with mocked API, submit a search, assert history entry appears

## Out of Scope

- Authentication
- Persistent history across page refreshes
- Mobile / responsive layout
